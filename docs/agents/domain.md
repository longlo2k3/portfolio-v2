# Domain Docs

This repo uses a single-context layout: `GLOSSARY.md` and `docs/adr/` at the repo root.

Before exploring an area, read the root glossary and relevant ADRs if they exist. Proceed when they do not; the domain-modeling skill creates them when terms or decisions are resolved.

Use glossary terms in issues, proposals, tests, and code. If a needed concept is absent, reconsider the term or note the gap for domain modeling. Surface any conflict with an existing ADR explicitly.
